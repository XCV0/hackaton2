# Методика метрик

Код: `backend/app/core/evaluate.py` (единственный модуль, читающий `dev_gold`; тест `test_pipeline_never_reads_gold`
проверяет, что остальной код эталон не читает). Отчёты: `reports/metrics_<domain>_<split>.json`, UI «Метрики качества».

## Порядок
1. Обрабатываются все публикации набора (dev: D001–D021), эталон в этот момент не читается.
2. Экспорт строится из БД (те же записи, что видит UI; отклонённые человеком исключаются).
3. Только затем выполняется сопоставление с полным эталоном.

## Правило сопоставления (одного числа недостаточно)
Внутри публикации — жадное взаимно-однозначное сопоставление, от строгого уровня к слабому:

| Уровень | Условие |
|---|---|
| **L3 (основной)** | та же `source_page`; то же число с точностью до опубликованного округления (как в проверщике RAG-комплекта: `0.42` совместимо с `0.4215`); та же каноническая метрика (EM/F1/Accuracy/nDCG… по словарю алиасов области) и тот же `k`; **RAG:** совпадают набор данных (`dataset_name`, токенная близость) и конфигурация (`rag_variant`/`generator_model`); **солнечные:** совпадают `aggregation`, направление развёртки измерения и `result_origin` |
| L2 | страница + число + метрика + k |
| L1 | страница + число |

Precision = совпавшие / извлечённые (extraction_status=extracted); Recall = совпавшие / эталонные extracted; F1 — гармоническое среднее.

## Срезы
обычные PDF / сканы; таблица / текст / рисунок (у предсказаний — по evidence.kind ноды, у эталона — по source_table/source_figure);
primary / cited; «только значения, подтверждённые кворумом» (до/после кворума); подмножество «напечатанных» значений эталона.

## Важная оговорка про эталон RAG
79 % строк `results.csv` эталона RAG dev — значения, **оцифрованные с графиков** (`raw_value` начинается с `~`, в `note`
«digitized», «vector point», «geometry audit»; например, 28 649 строк D014). По ТЗ (раздел 7) оцифровка кривых
запрещена, поэтому полнота на полном эталоне принципиально ограничена; основным ориентиром служит подмножество
«напечатанных» значений (8 003 строки).

## Технические показатели (dev и test)
покрытие публикаций; доля буквально подтверждённых цитат (и только через OCR); доля значений с ручной проверкой;
исходы кворума; замечания по типам; число запусков нод, токены, время, стоимость (если в настройках указаны цены).
На **test** precision/recall не сообщаются — эталона нет.

## Канонизация и соглашения по полям (RAG, с 22.11.2026)

Ноды читают статью постранично, поэтому одна сущность может появиться несколько раз: в аннотации, в столбце Table 1
и в строке Table 2. После извлечения выполняется шаг канонизации (`backend/app/core/canon.py`). Каждое решение пишется
в `note` сущности или значения и в журнал обработки публикации (`corpus.stats.canonicalization`).

| Правило | Когда срабатывает | Что не делается |
|---|---|---|
| Одинаковое имя | имена совпадают, ни одно поле не противоречит («test» и «test (250 q.)» совместимы) | разные версии, сплиты и модели не сливаются |
| Подпись внутри описания | у сущности есть только подпись, и эта подпись записана в описании ровно одной более полной сущности той же таблицы | при двух и более кандидатах слияния нет |
| Повтор значений | у сущности есть только подпись, и все её значения напечатаны для ровно одной другой сущности (аннотация повторяет таблицу) | — |
| Задача | имя задачи — подмножество слов ровно одной другой задачи | — |
| Эксперименты | в статье один набор данных и одна задача, а размер выборки и стоимость не противоречат друг другу | эксперименты цитируемых результатов остаются отдельными |
| Колонтитул | имя напечатано только в повторяющемся колонтитуле страниц | — |
| Пустая сущность | нет ни имени, ни содержания | — |

Ссылки значений на удалённую сущность переводятся на единственную оставшуюся сущность этой таблицы, а если такой нет —
очищаются. Это тоже записывается в `note`.

Соглашения по полям `results` (RAG):
- **Единица долей.** Если в статье прямо сказано, что метрики даны в шкале 0–1 («fractions on the 0-1 scale»), то
  ограниченной метрике без напечатанной единицы ставится `metric_unit = normalized_unit = fraction`; значение не пересчитывается.
  Если шкала не заявлена, единица остаётся пустой: «шкала как опубликована, не указана». Проценты остаются `%`.
- **Направление.** `metric_direction` берётся из определения метрики (`domains/rag.yaml`): качество — `higher_is_better`,
  задержка и токены — `lower_is_better`. У разниц направление не ставится.
- **Разница.** «improves F1 by 3.3 points relative to BM25» — это не значение F1. Запись называется `F1 delta`,
  `metric_variant = difference vs BM25`, в `note` указана базовая конфигурация. Правило `delta_consistency` сверяет разницу
  с абсолютными значениями таблицы (0.684 − 0.651 = 3.3 п.).
- **Название метрики.** Внутри одной публикации одна метрика пишется одинаково («EM» и «Exact Match» → самое частое
  написание), а напечатанное написание сохраняется в `note`. Проверщик RAG-комплекта сравнивает `metric_name` у `duplicate_of`
  буквально, поэтому без этого повторы нельзя связать.
- **OCR-ошибка в названии метрики.** На скане имя, отличающееся от известной метрики одним символом, причём один из двух
  символов — цифра (FA ↔ F1), исправляется только если эта метрика напечатана в текстовом слое статьи. Исходное прочтение
  и страницы-основания хранятся в `evidence.ocr_metric_fix` и в описании замечания `ocr_uncertainty`.
- **Повторы.** Значение, повторённое в аннотации, обсуждении или подписи рисунка, получает `duplicate_of` на запись из
  таблицы. Поля, которые повтор не указывает (эксперимент, задача, размер выборки, единица), берутся из основной записи,
  и это отмечается в `note`. Если число отличается — создаётся замечание `contradiction`, обе записи сохраняются.
  Исключение — число с рисунка: оно отправляется на визуальную проверку.
- **Граница цитаты.** Если фрагмент найден, но число стоит после него (например, «… Recall@10 =» и значение на следующей
  строке), цитата расширяется до предложения на той же странице и в тексте того же движка, после чего проверка повторяется.
  Страницы и движки не смешиваются. Если расширение не прошло проверку, значение остаётся «нужна проверка». В интерфейсе
  «фрагмент найден» и «число во фрагменте» показываются отдельно.
