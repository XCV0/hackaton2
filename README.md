# Evidence Extractor — доказуемое извлечение данных из научных PDF (ВИНИТИ РАН × ЮФУ)

Сервис извлекает из PDF-публикаций структурированные сведения по официальным схемам двух предметных
областей — **тонкоплёночные солнечные элементы** и **RAG-системы** — и для каждого значения хранит
проверяемое происхождение: публикация → страница PDF → раздел/таблица/рисунок → дословная цитата.
Это не чат-бот: каждое значение проходит машинную проверку источника, предметные правила и, при
сомнении, ручную проверку с аудитом.

## Запуск

```bash
cd hackaton2
python3 -m venv .venv && .venv/bin/pip install pymupdf pypdf fonttools fastapi "uvicorn[standard]" httpx pydantic python-multipart pytest pyyaml
brew install tesseract            # OCR для сканов (тот же движок, что у официального проверщика --ocr)
(cd frontend && npm install && npm run build)
.venv/bin/uvicorn backend.app.api:app --host 127.0.0.1 --port 8077
```

Откройте http://127.0.0.1:8077. Ключ LLM вводится на сайте: **Администрирование → LLM и ноды** (провайдер,
ключ, модели нод A/B/C/Vision, reasoning effort, параллельность). По умолчанию — AgentRouter (`/v1/responses`).

Корпус подключается символическими ссылками (исходные PDF и проверщики не изменяются):
`data/domain1_solar → Кейс5_область1_участникам`, `data/domain2_rag → RAG_ВИНИТИ_участникам_2026-11-20`.

CLI (то же ядро, что и UI):

```bash
.venv/bin/python -m backend.cli process  --domain rag --split dev [--pub D001 D002] [--mode extended]
.venv/bin/python -m backend.cli export   --domain rag --split dev --out runs/export/rag_dev
.venv/bin/python -m backend.cli evaluate --domain rag --split dev     # только dev, после обработки
.venv/bin/python -m pytest -q backend/tests
```

## Архитектура

Одно предметно-независимое ядро; области подключаются конфигурацией (`backend/app/domains/{rag,solar}.yaml`
— словари, нормализация, правила) и официальными шаблонами CSV (колонки читаются в рантайме).

```
PDF ─► регистрация (SHA-256, страницы) ─► текстовый слой pypdf + PyMuPDF ─► OCR Tesseract для страниц без текста
    ─► сегментация (заголовки разделов, подписи Table/Figure, геометрия таблиц по словам/OCR-боксам)
    ─► ноды извлечения:  R  детерминированная (таблицы + шаблоны текста), всегда
                         A  LLM по всему корпусу (постранично, параллельно; сущности сливаются по меткам)
                         B  LLM другой моделью (расширенный режим)          C  точечное перечитывание страницы
                         V  Vision: только напечатанные числа на рисунках
    ─► сохранение сырого ответа каждой ноды (node_runs: модель, параметры, промпт, вход, ответ, токены)
    ─► нормализация (raw сохраняется, трасса правила)  ─► проверка источника (буквальная цитата на той же странице
       в одном из движков pypdf / PyMuPDF / OCR; число в цитате или в ячейке таблицы)
    ─► сравнение нод после нормализации (agree / disagree / single; C при расхождении, бюджет ограничен)
    ─► предметные правила (issue с формулой и числами; значение не переписывается)
    ─► verified / flagged / needs_review  ─► SQLite ─► UI и админка ─► экспорт CSV + отчёты + официальный проверщик
```

| Модуль | Назначение |
|---|---|
| `core/pdftext.py` | извлечение текста двумя движками, OCR, рендер страниц, нормализация цитат (копия официальной) |
| `core/segment.py` | строки, заголовки разделов, подписи, геометрический парсер таблиц |
| `core/extract_rules.py` | нода R |
| `core/extract_llm.py`, `core/llm.py` | ноды A/B/C/V, клиент LLM с пресетами провайдеров |
| `core/normalize.py`, `core/rules.py` | нормализация, предметные правила обеих областей |
| `core/quotes.py` | проверка цитат и привязки числа |
| `core/pipeline.py` | оркестрация, кворум, статусы, задачи |
| `core/export.py`, `core/evaluate.py` | экспорт и официальный проверщик; метрики (единственный модуль, читающий dev_gold) |
| `api.py` | HTTP API для UI и админки |
| `frontend/` | React + TypeScript: обзор, каталог, результаты, карточки, просмотр источника, сравнение, экспорт, админка |

### Статусы
- **verified** — цитата буквально найдена на указанной странице текстового слоя, число есть в цитате или в ячейке
  таблицы, ноды не разошлись, правила не нарушены. Это подтверждение *опубликованного текста*, а не научной истинности.
- **flagged** — источник подтверждён, но нарушено предметное правило (возможное внутреннее противоречие статьи).
- **needs_review** — происхождение машинно не доказано: цитата не найдена, только OCR, рисунок, расхождение нод.
- Ручные решения: confirmed / corrected / rejected (+комментарий, история, отклонённые не экспортируются).

Подробнее: `REQUIREMENTS.md` (требования → реализация → проверка), `PROGRESS.md` (что сделано и проверено),
`reports/` (фактические отчёты проверок и метрики).
